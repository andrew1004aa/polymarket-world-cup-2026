\section{Data}
\label{sec:data}

\subsection{Data sources and canonical trade sample}

This dissertation draws on three linked public sources. Trade-level records
were collected from the public Polymarket Data API separately for each of the
360 condition IDs. Each request returned at most 1,000 records and was paginated
by offset. Because the endpoint imposes a finite offset range, any time window
that reached that range was divided recursively until all pages could be
retrieved. Every request covered a half-open interval, $[s,e)$, so a timestamp
at a boundary belonged to exactly one adjacent window. Successful responses
were stored as resumable checkpoints before the consolidated file was built.

The API does not supply a single fill-level trade ID. Transaction hash was
retained as a field but was not used as a unique trade key because one
transaction can contain multiple returned fills. Instead, exact identity of
the complete API record was used to prevent the same response row from being
written more than once when checkpoints and adjacent pages were consolidated.
The resulting 6,725,732 API records across 360 markets form the sole canonical
trade sample. Summed market-level counts were then compared with an independent
Dune extraction: 350 markets agreed exactly and Dune contained one additional
record in each of ten markets. This ten-record difference did not alter the
canonical Polymarket sample, and Dune observations were not appended to it.

The requests used the endpoint's default \texttt{takerOnly=true} setting. The
returned \texttt{side} field records \texttt{BUY} or \texttt{SELL} from the
reported user's perspective; it is used together with the outcome token to
construct YES-equivalent direction and is not interpreted as a maker--taker
role classification. Price-history records come from the CLOB price-history
endpoint at one-minute fidelity; prices are never interpolated or resampled.
The endpoint documents each observation as a timestamp and price value but does
not identify that value as a contemporaneous midpoint or pre-trade quote.
Accordingly, the outcome is described throughout as a recorded-price adjustment.
Match timing and outcomes come from a separately reviewed FIFA fixture table.

The observation window spans 2026-06-01T00:00:00Z to
2026-08-01T00:00:00Z, with the end point excluded. Within this window the canonical trade sample
contains 6,725,732 records across 360 binary markets: 312 home-win,
away-win, or draw contracts nested in 104 FIFA World Cup matches, and 48
country outright-winner contracts. The associated price dataset contains
17,980,605 raw CLOB price-history points for the 720 corresponding YES and
NO tokens. The collection report, data dictionary, dependency files and
principal non-confidential outputs accompany the code at
\url{https://github.com/andrew1004aa/polymarket-world-cup-2026}. The submitted
version cites a fixed release tag, so later repository changes
cannot silently alter the documented workflow.

\subsection{Sample separation principles}

Three separations are applied consistently to the canonical sample before it
is aggregated into any model-ready panel. First, match contracts and country
outright contracts are analysed as separate families throughout, because
their horizons, resolution timing, and information environments differ; no
result pools the two families. Second, match-market observations are split
by phase: pre-kickoff observations form the primary sample for H1, H2, H3a, H3b and RQ4,
post-kickoff/pre-resolution observations are analysed separately because
match events generate fundamental information, and trades at or after
recorded resolution are retained only in a method-neutral audit panel and
excluded from every model sample. The post-kickoff phase is not labelled
purely in-play because actual final-whistle timestamps are unavailable.
Third, trades within the same market and UTC minute are aggregated into a
single market-minute observation before any price response is calculated,
because the price-history endpoint has one-minute fidelity and several
trades can share the same observed price outcome.

The wallet-heterogeneity and whale samples share the same 2,395,771-action
evaluation window but classify wallets from different histories: the
high-activity proxy ranks wallets using only their own trailing or expanding
activity, whereas the whale proxy ranks wallets by cumulative gross USDC
across all 6,725,732 canonical trades in the full 360-market universe. The
two proxies are conceptually and operationally distinct (Section~\ref{sec:wallet-heterogeneity-design}, Section~\ref{sec:whale-wallet-design})
and are not interchangeable, even though both are evaluated over the same
action sample.

The 1,000-prior-trade eligibility rule limits the H2 conclusion to markets with
adequate observable trading history. Expanding history includes 252 markets and
excludes 60; rolling history includes 236 and excludes 76. Under expanding
history, included markets average 18,878 trades and $4.76 million in recorded
volume, compared with 9,309 trades and $1.60 million among excluded markets.
Their mean baseline probabilities are also higher (0.367 versus 0.196), and
their pre-kickoff analysis histories are longer (2,619 versus 1,473 observed
market-minutes). Rolling-history comparisons show the same pattern. Stage shares
are broadly similar, but the eligibility rule selects more active, longer-lived,
and generally higher-probability contracts; the findings are not generalised to
thin markets without sufficient prior history.
